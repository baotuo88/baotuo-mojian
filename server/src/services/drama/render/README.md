# 短剧成片合成边界

## 背景与范围

新手需要从已完成的镜头和配音直接得到可下载的视频。合成只是确定性的媒体处理，不调用 AI、不生成缺失素材，也不隐式提交付费视频任务。缺镜头视频、配音地址失效或分镜过期时，先让用户补齐对应素材。

外部模块只通过 `render/index.ts` 使用 `dramaRenderService`。`domain/`
校验时间线及资源限制，`application/` 管理持久任务与版本保护，`infrastructure/`
负责受限下载和 FFmpeg 子进程。

## 任务与版本契约

- `start(projectId, episodeOrder)` 锁定当前台本版本后创建
  `DramaRenderJob`，保存分镜 ID、来源修订号和完整时间线快照。同一集同时只能有一个排队或执行中的任务；重复点击返回该任务。
- 合成只读取
  `snapshotJson`，不在执行中拼接后来生成的素材。快照属于内部状态，不返回前端。
- 状态为
  `queued → running → succeeded | failed | cancelled`。进度 0–100。一个 API 进程最多同时运行一个合成，最多接收 20 个未完成任务。
- 保存成功结果前再次取得台本锁，在锁内重新导出时间线，与快照做指纹比对。台本、分镜或媒体变化时，任务失败并提示重新合成；已输出文件仍保存为历史结果。
- `list` 返回
  `isCurrent`，同时比较台本修订和当前完整时间线。相同分镜上重做视频或配音也会使历史成片不再代表当前素材；历史任务保持原始成功状态及下载地址。
- `cancel`
  只取消合成，不删除源视频或配音。发布期间取消时，已写出的文件可作为该取消任务的历史结果保留。
- 启动调用 `recoverInterruptedJobs()` 将遗留排队/执行任务置为
  `failed`，保留素材并提示用户重试；绝不偷偷恢复旧制作快照。
- 关机调用
  `shutdown()`，等待正在运行的 FFmpeg 子进程退出后清理任务临时目录。不要在数据库断开之后调用。
- 当前恢复和排队模型只支持单 API 实例。增加多个 API 副本前必须引入全局 worker 租约，不得让多个实例相互恢复或清理对方任务。

## 媒体处理规则

1. 视频逐镜头规范化为 720×1280、30
   fps、H.264/AAC。画面等比缩放留黑边，不裁掉内容；短视频以最后一帧补齐镜头时长。
2. 镜头有 TTS 时使用配音时间线替换该镜头原音轨；没有 TTS 时保留原声音；素材没有声音则补静音。合成以 FFprobe 测得的实际配音时长重排本镜头对白字幕及后续镜头，必要时延长末帧。供应商没有返回时长时，不能按导出中的估算时长截断对白。该测量只影响本次成片排布，不覆盖用户的镜头规划或素材记录。
3. 字幕按时间线烧录到画面，Docker 自带 Noto
   CJK 字体。成片可以直接播放，无需单独加载字幕文件。
4. 规范化镜头使用相同编码参数后拼接，检查实际时长及音视频轨道，再通过媒体存储文件接口发布。成片不整体读入 Node 内存。

## 下载、进程与存储限制

- 本地输入只接受
  `/api/media/assets/{tts|video|music}/{filename}`。解析路径和真实路径双重校验，禁止文件或目录符号链接越过媒体根目录。
- 远程输入只允许标准端口的 HTTP/HTTPS，不接受凭据、内网、回环、链路本地、保留地址及 IPv6 过渡地址。域名全部解析结果都必须公开可路由；每次连接固定到已核验 IP，避免 DNS 重绑定。最多跟随 3 次重定向，每次重新验证。
- 下载流按单素材和整个任务统计字节数，有独立超时并继承任务取消信号，不把下载内容整体读入内存。
- 兼容供应商返回的 `data:audio/...;base64,...`
  音频内容导入：只接受标准音频 MIME、严格且规范的 Base64，每段最多 32
  MiB 并计入任务输入预算。导入到任务临时文件后仍走同一 FFprobe 解码限制。拒绝视频、HTML、其他 MIME 与非 Base64 数据，不触发网络访问。
- FFmpeg 只读取服务已下载的本地文件。禁止网络协议及 playlist 等格式；命令通过
  `spawn(executable, args)`
  执行，不经 shell。一次进程只消费一个镜头及最多 64 段配音。
- 子进程收到取消后先 SIGTERM，3 秒未退出则 SIGKILL；进程关闭前不清理其文件，也不启动下一任务。
- 临时文件位于媒体根目录
  `.render-work/{jobId}/`，仅该任务结束或启动恢复时清理。用户素材与发布成片不在此目录。
- 开始前要求可用磁盘至少为输入预算 + 三倍输出预算 + 50
  MiB，覆盖规范化镜头、临时成片和发布复制的峰值；规范化镜头总大小和最终结果都受输出预算限制。

| 环境变量                                   | 默认                 | 硬上限                            |
| ------------------------------------------ | -------------------- | --------------------------------- |
| `DRAMA_FFMPEG_PATH` / `DRAMA_FFPROBE_PATH` | `ffmpeg` / `ffprobe` | 可执行文件路径，不接受 shell 参数 |
| `DRAMA_RENDER_THREADS`                     | 2                    | 4                                 |
| `DRAMA_RENDER_MAX_DURATION_SEC`            | 600                  | 1800                              |
| `DRAMA_RENDER_MAX_CLIPS`                   | 80                   | 200                               |
| `DRAMA_RENDER_MAX_ASSET_MB`                | 256                  | 1024                              |
| `DRAMA_RENDER_MAX_INPUT_MB`                | 2048                 | 8192                              |
| `DRAMA_RENDER_MAX_OUTPUT_MB`               | 512                  | 2048                              |
| `DRAMA_RENDER_TIMEOUT_SEC`                 | 1800                 | 7200                              |
| `DRAMA_RENDER_DOWNLOAD_TIMEOUT_SEC`        | 120                  | 600                               |

## 验证与常见失败

`server/tests/dramaRender.test.js`
覆盖重复点击、取消与重试、启动恢复、旧素材拒绝发布、输入完整性、SSRF 和路径边界。存在 FFmpeg 时还会真实合成两个不同颜色镜头，校验竖屏分辨率、时长和声音频率，确认 TTS 覆盖原声、无 TTS 镜头保留原声。设置
`DRAMA_REQUIRE_FFMPEG=1` 可让缺少二进制变成测试失败。

远程链接过期应重新刷新供应商结果或保存到项目媒体；不要关闭地址保护绕过失败。视频素材未完成时不能以首帧静态图片伪装可交付成片。长片触发预算时应拆分单集或由管理员在文档上限内调整预算。
