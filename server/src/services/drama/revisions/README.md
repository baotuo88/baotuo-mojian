# 短剧台本修订与派生产物边界

## 背景与决策

台本是分镜和音视频的制作依据。后台 AI 或供应商可能在人工保存之后才返回，不能用“最后完成的请求获胜”处理创作数据。本模块拥有统一台本提交、版本锁、事实有效性与派生产物有效性；HTTP 和制作服务通过本目录 `index.ts` 使用这些规则。

## 当前规则

- `DramaEpisode.revision` 从 0 开始。人工保存必须携带读取时的 `expectedRevision`；AI 在请求前捕获版本，返回后走相同提交边界。版本不一致返回 409，不覆盖现稿。
- 每次有实际变化的保存递增版本，事务内保存修改前后的不可变 `DramaEpisodeRevision`。重复保存相同字段不产生新版本。历史素材不删除。
- 标题、钩子、卡点、时长和正文都属于分镜输入；这些字段变化清除旧审校并将已有分镜标为 `stale`。
- 只有正文变化使剧情事实过期。仅修改标题等元数据保留事实并绑定新版本。AI 生成和修复必须提供当前整集的完整事实快照，不能只给相较旧稿的差量。
- 人工正文修改后 `factsStatus=pending`。后续集数进入 AI 创作上下文前，自动用注册提示词整理待更新的前序事实；完成时再次核验正文版本。AI 整理失败显式报错，不用空账本掩盖失败。
- 上下文只读取本集之前、未过期的事实；源事实保留。未来集数的结果不能进入前序台本上下文。
- 审校结果独立 CAS：同时检查台本版本和读取时的质量标记，防止晚到的质量/合规结果覆盖新审校。

## 分镜与媒体

分镜记录 `sourceRevision`。生成分镜在台本锁内递增分镜版本并标旧分镜 `superseded`；当前分镜按 `version / createdAt / id` 降序统一选取，且必须匹配台本版本、非过期状态。

`lockEpisodeRevision` 使用参数化无值变更 UPDATE 获取行锁，不更改 `updatedAt`。台本、分镜和媒体写回都先持有同一集的锁，避免检查通过后台本又被并发修改。不得先取得集锁再申请项目锁，避免与规划阶段的项目→集锁顺序形成死锁。

`withCurrentShot` 在事务中检查当前分镜，再允许媒体服务提交自己的 CAS。数据库版本保护不能代替文件保护：首帧使用不可变文件，旧请求只能留下独立文件，不能覆盖已发布图片。付费视频的迟到任务编号保留供核对，过期结果不当作当前素材。

## 失败与用户引导

409 冲突必须保留本地稿，提供复制/下载和明确丢弃后重新载入，不自动覆盖或替用户强行保存。台本修改后引导重新生成分镜和媒体，历史稿与素材可保留对照。成片绑定时间线快照，同分镜重做音视频也会使旧成片成为历史结果。

影响范围仅短剧工作台，不改变小说自动导演或章节质量债务规则。
