# 单话图片生产

`ComicBatchOrchestrator` 是兼容入口，`EpisodeBatchProduction` 负责确认范围落库、执行领取、并发池、进度和恢复；`BatchContract` 定义持久任务与只读状态投影。其他漫画模块通过 `index.ts` 读取租约合同，不各自推测“运行中”。

- 每话最多一个有效批量任务。创建和恢复先锁定 `ComicEpisode` 行，再检查活动租约；规划替换也使用这个行锁。
- 任务持久保存话 ID、目标格 ID、源指纹、初始图片版本、图片平台和模型。估算返回范围指纹，前端将用户确认的指纹带回创建请求。
- 心跳与进度 JSON 写入串行化，并用完整旧 JSON 做条件更新。进度保存失败停止后续派发，不能继续付费且吞掉数据库错误。
- Worker 在独立 execution scope 下运行，附带 `comic_batch` 围栏。共享 Prisma 将租约检查和图片发布放在同一个短事务；模型调用不占用数据库事务。
- 过期租约只投影为 `interrupted`，不在查询或启动时自动发送图片请求。用户确认继续后只处理未完成格；原模型配置变化必须重新确认创建。
- 图片服务使用独立版本路径，停止后的迟到文件不会覆盖已确认图片。具体来源规则由 `assets` 所有，生产模块不能扫描目录猜测成功。

详细合同见 [漫画批量生产与恢复](../../../../../docs/wiki/workflows/comic-batch-recovery.md)。
