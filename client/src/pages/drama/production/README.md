# 短剧制作状态展示边界

## 职责

本模块将短剧项目已有的结构化状态映射到任务卡、下一步入口和运行安全门禁。素材理解、赛道、分集内容和质量判断仍由后端 AI 合同负责；前端不得从台本文本、错误消息或关键词猜测制作意图。

`projection.ts` 处理任务筛选、当前分镜归属、视频状态及分集缺口；`nextStep.ts`
展示这些状态与 AI 产物对应的操作入口；`DramaBatchJobCard`
展示同一持久化任务，外部页面经 `index.ts` 使用。

## 运行与恢复

- `pending` / `running` 任务轮询项目状态；暂停请求等待当前镜头完成，按钮依据
  `pauseRequested` 防重复提交。
- `paused` / `failed`
  即使没有失败镜头 ID，也必须保留恢复入口。历史未完成任务不因最近任务数量限制消失。
- 恢复以任务 ID 为单位，确认额外费用后发送
  `confirmAdditionalCost: true`。不得创建新批任务来模拟恢复，也不得把当前下拉选择覆盖到原任务设置。
- 完成镜头、生成通道、参考图设置和已用费用由后端任务快照维护。分镜 ID 不一致时不允许恢复；用户进入本集，基于当前分镜重新制作。
- 费用是按配置单价的估算；没有单价不代表免费，也不是供应商最终账单。

## 视频状态

只轮询当前分镜最新、非历史、带供应商任务 ID 的 `queued` / `running`
视频，串行发送状态刷新请求。失败后停止自动刷新并提供显式重试，避免重复错误请求。

`submitting` / `submission_unknown`
不触发供应商轮询或自动重发。提交结果待确认或失败的视频需要用户核对生成通道并明确确认重试费用后，才能重新提交。`succeeded`
必须有可用结果地址才进入完成引导。

历史分镜和旧提示词不参与当前制作进度。分集续规划只补齐目标范围内第一个连续缺口，不重写已有台本；完成进度以目标集数为分母。

## 验证

`client/tests/drama/productionProjection.test.mjs`
覆盖恢复入口、轮询终止、历史版本、目标集数和未完成视频的展示边界。界面交互验收由用户完成。

## 台本版本与成片入口

- `currentStoryboard` 只接受 `sourceRevision === episode.revision` 且未标记为
  `stale` / `superseded`
  的分镜，以最高分镜版本为准。缺少版本标识时不能推断为当前有效分镜。
- 视频、配音、费用预估和批任务恢复必须使用同一分镜投影。预估缓存还需绑定分镜 ID 与台本版本，避免重新生成分镜后沿用旧集的报价。
- 失效素材可作为历史查看，但不能计入当前制作完成状态。台本修改后，“下一步”先引导检查台本和重建分镜。
- 镜头完成后，下一步打开“合成与导出”，不自动下载台本代替成片制作。
- `index.ts` 是界面调用入口；`model.ts`
  是无 React 依赖的公开状态门面，供成片模块等消费当前版本投影。其他模块不应自行用数组首元素推断当前分镜。
