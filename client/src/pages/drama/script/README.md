# 短剧台本编辑边界

## 背景

台本生成、人工编辑、自动修复和制作任务轮询可能同时发生。服务器返回的新台本不能直接赋值到正在编辑的输入框，否则一次轮询就会丢失用户的文字。

## 当前规则

- 草稿按项目及分集 ID 隔离，`baseRevision`
  是开始编辑时的服务器版本；保存必须发送此版本作为 `expectedRevision`。
- `draftState.ts` 管理草稿、基线和冲突的纯状态转换；`useEpisodeDrafts`
  管理网络、会话暂存与页面生命周期；`DramaDraftProtection`
  提供复制、下载、历史稿及明确丢弃操作。页面通过 `index.ts`
  使用，不自行实现保存状态机。
- 未编辑的草稿可以跟随服务器版本更新。存在本地编辑时，较新服务器版本只能标记冲突，不能覆盖草稿。版本比保存响应更旧的缓存也不能回退草稿。
- 保存期间仍可输入。保存响应只确认提交时的文字，随后键入的内容保留为下一次未保存编辑，并以返回的版本继续保存。
- HTTP
  409 后保留本地稿，不更改其期望版本，也不自动覆盖重试。用户可复制或下载；“载入服务器稿”必须明确确认丢弃本地编辑，并重新读取服务器成功后才替换。
- 草稿放在项目页面层，切换分集或页签不会卸载草稿状态；同一浏览器会话通过
  `sessionStorage`
  暂存未保存稿。它不是服务器备份，容量不足时提示下载，关闭页面仍对未保存内容给出浏览器提示。
- 历史稿只供查看、下载和人工合并，不允许历史稿查看动作隐式恢复服务器台本。

## 验证与维护

`client/tests/drama/scriptDraftState.test.mjs`
覆盖轮询、并发编辑、保存后继续输入、缓存回退、会话恢复及损坏暂存数据。未来增加台本字段时，必须同时更新基线比较、暂存校验和本地稿下载内容。界面交互验收由用户完成。
