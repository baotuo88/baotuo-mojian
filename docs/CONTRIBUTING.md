## 开发流程

### 1. Fork 项目

点击仓库页面右上角的 "Fork" 按钮。

### 2. 克隆到本地

```bash
git clone https://github.com/your-username/baotuo-mojian.git
cd baotuo-mojian
```

### 3. 添加上游仓库

```bash
git remote add upstream https://github.com/original-org/baotuo-mojian.git
```

### 4. 创建功能分支

```bash
git checkout -b feature/your-feature-name
```

分支命名规范：
- `feature/` - 新功能
- `fix/` - Bug 修复
- `docs/` - 文档更新
- `refactor/` - 代码重构
- `test/` - 测试相关

### 5. 进行开发

遵循[开发者指南](./DEVELOPER_GUIDE.md)中的规范。

### 6. 提交代码

```bash
git add .
git commit -m "feat(novel): 添加章节导出功能"
```

提交信息格式：

```
<type>(<scope>): <subject>

[optional body]

[optional footer]
```

### 7. 保持同步

定期同步上游仓库的更新：

```bash
git fetch upstream
git rebase upstream/main
```

### 8. 推送到 Fork

```bash
git push origin feature/your-feature-name
```

## Pull Request 流程

### 1. 创建 PR

在 GitHub 上从您的分支创建 Pull Request 到主仓库的 `main` 分支。

### 2. PR 标题

清晰描述您的更改：

- ✅ `feat(novel): 添加章节自动审核功能`
- ✅ `fix(llm): 修复 DeepSeek 调用超时问题`
- ❌ `更新代码`
- ❌ `修复 bug`

### 3. PR 描述模板

```markdown
## 更改类型

- [ ] Bug 修复
- [ ] 新功能
- [ ] 性能优化
- [ ] 代码重构
- [ ] 文档更新
- [ ] 其他

## 更改内容

简要描述您的更改...

## 测试

- [ ] 已添加单元测试
- [ ] 已添加集成测试
- [ ] 手动测试通过

## 相关 Issue

Closes #123

## 截图（如适用）

（添加截图）

## 检查清单

- [ ] 代码遵循项目规范
- [ ] 通过所有测试
- [ ] 更新了相关文档
- [ ] 无 TypeScript 类型错误
- [ ] 通过 ESLint 检查
```

### 4. CI 检查

确保所有 CI 检查通过：

- ✅ 类型检查
- ✅ ESLint
- ✅ Prettier
- ✅ 单元测试
- ✅ 构建成功

### 5. 代码审查

维护者会审查您的代码并提供反馈。请及时响应评论和建议。

### 6. 合并

审查通过后，维护者会合并您的 PR。

## 报告 Bug

### Bug 报告应包含：

1. **标题**：简短描述问题
2. **环境信息**：
   - 操作系统
   - Node.js 版本
   - 浏览器版本（前端问题）
3. **复现步骤**：详细的步骤
4. **期望行为**：应该发生什么
5. **实际行为**：实际发生了什么
6. **截图/日志**：如果适用
7. **其他信息**：任何可能相关的细节

### Bug 报告模板

```markdown
**环境信息**
- OS: macOS 13.0
- Node.js: v22.0.0
- Browser: Chrome 120

**复现步骤**
1. 打开小说编辑页面
2. 点击"自动导演"按钮
3. 选择"开始创作"

**期望行为**
应该开始章节生成流程

**实际行为**
页面显示 500 错误

**错误信息**
```
Error: LLM provider not configured
  at llmRouter.ts:45
```

**其他信息**
在配置了 OPENAI_API_KEY 后依然出现此错误
```

## 提出新功能

### 功能请求应包含：

1. **问题描述**：要解决什么问题
2. **解决方案**：您建议的实现方式
3. **替代方案**：考虑过的其他方案
4. **使用场景**：谁会使用，如何使用
5. **影响范围**：对现有功能的影响

### 功能请求模板

```markdown
**问题描述**
作为一个小说作者，我希望能够批量导出多个章节，这样可以一次性获取整卷内容。

**建议的解决方案**
在卷章列表页面添加"批量导出"按钮，支持：
- 选择多个章节
- 选择导出格式（txt, docx, epub）
- 合并成单个文件或分别导出

**替代方案**
1. 在每个章节旁边添加导出按钮（但需要逐个操作）
2. 提供命令行工具进行批量导出

**使用场景**
- 小说作者完成一卷内容后想要备份
- 需要提交给出版社审阅
- 在其他平台发布

**影响范围**
- 需要新增批量选择 UI
- 后端需要支持批量导出 API
- 不影响现有单章节导出功能
```

## 常见问题

### Q: PR 被拒绝了怎么办？

**A**: 这很正常！维护者会说明原因。您可以：
1. 根据反馈修改代码
2. 在 PR 中讨论不同意见
3. 如果确实不合适，可以关闭 PR

### Q: 我的 PR 长时间没有回应？

**A**: 维护者可能在忙其他事情。您可以：
1. 礼貌地评论询问进度
2. 在社区讨论群中提醒
3. 耐心等待（开源项目通常响应较慢）

### Q: 可以同时提交多个 PR 吗？

**A**: 可以，但建议：
1. 每个 PR 只解决一个问题
2. 等第一个 PR 合并后再提交相关的 PR
3. 避免 PR 之间有依赖关系

### Q: 功能开发到一半可以提交 PR 吗？

**A**: 可以，标记为 "Draft PR" 或在标题前加 `[WIP]`。这样可以：
1. 早期获得反馈
2. 展示开发进度
3. 与维护者讨论实现方向
