# 格式检查与历史债务边界

## 背景

仓库启用完整格式检查时，稳定分支已有大量不符合现有 Prettier 配置的文件。一次性格式化全部历史文件会扩大功能发布的审查范围，也容易与正在进行的工作冲突。仅检查 Git
diff 又会漏过新增文件或依赖不完整的 CI checkout。

因此，格式检查保留完整的源码候选范围，同时使用内容哈希识别尚未修改的历史格式债务。历史债务不等于格式合格，检查结果必须分别报告二者。

## 当前规则

- `pnpm format:check` 通过 `scripts/format-check.cjs`
  执行真实 Prettier 检查，不修改文件。
- 候选文件来自 Git 已跟踪文件及未被 Git 忽略的新增文件。构建产物仍遵循
  `.prettierignore`。备份、依赖和其他未跟踪临时文件不会因位于工作目录而误入检查。
- 扩展名沿用原检查的 `ts/tsx/js/jsx/json/css/md`，另显式检查格式检查器及其测试的
  `cjs` 文件。其他历史 `cjs/mjs`
  文件未纳入既有格式范围；将来扩大范围需单独整理，不允许借机给新代码添加豁免。
- 每个候选文件先运行 Prettier。解析失败、配置错误、文件读取错误、Git 读取失败及检查器异常均失败，不能转成历史债务。
- 只有格式不合格、路径在固定基线中、且当前完整文件字节的 SHA-256 与基线相同的文件，才计为历史债务。内容变化、改名或新文件均不继承豁免。
- 已格式化的历史文件立即计为合格，不要求先删除对应条目。已删除文件不再计入当前债务。

## 基线来源与维护

`scripts/quality/format-baseline.json` 只记录稳定分支提交
`380cb946d73febc03cbe47832aa653fe4176b9fb` 中已有、在待发布提交
`4e9fd5b3f5c58a09c8059b9fbdb298e3ea7038de` 中仍为同一 Git
blob、且当时确实不符合 Prettier 配置的 1,678 个文件。当前 beta 新增或修改的文件不在此次历史豁免范围内。

基线文件随代码提交，使浅克隆 CI 不必获取所有历史 Git 对象。检查器直接校验当前文件内容，不能用修改时间、是否在当前 diff 中或文件路径前缀替代哈希比较。

基线只减不增：

1. 修改历史文件时，先使用仓库现有 Prettier 配置格式化该文件，再提交功能修改。
2. 已规范或已删除的文件可从基线移除。无需为每个文件单独修改基线；当前债务计数会自动下降。
3. 禁止添加条目、修改已有条目的哈希、复制条目到新路径，或重新加入已移除条目来放过新变更。审核基线 diff 时，允许的文件映射变化只有删除。
4. 不提供生成、刷新或接受新债务的日常命令。配置或 Prettier 版本调整应单独审核其影响，并修复由调整产生的新格式错误，不能自动重建基线。
5. `sourceCommit` 与 `comparisonCommit` 是固定来源证据，不能随分支前进而重置。

这是一项增量清偿历史债务的审查合同，不能防止有人同时篡改检查器和基线。任何检查器、基线及忽略规则变更都必须检查是否扩大豁免范围。

## 排查与验证

- `Changed historical file must be formatted`
  表示文件内容已不同于冻结内容：格式化当前文件，不要更新哈希。
- `New or changed file must be formatted` 表示没有适用的历史豁免：使用
  `pnpm exec prettier --write <文件路径>` 修复。
- `Formatter error`
  表示语法、配置或读取异常：先修复具体错误，不能通过加入基线消除。
- 汇总中的 `unchanged historical debts`
  需要持续减少；检查成功不代表仓库已没有格式债务。
- 使用 `node --test scripts/tests/format-check.test.cjs`
  验证内容变化、新文件、改名、解析错误、配置错误和 Git 候选范围等关键边界。

本规则仅影响代码格式验证，不改变小说、漫画、短剧运行时流程或用户数据。
