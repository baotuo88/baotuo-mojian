# 漫画参考图恢复与导出错误投影

## 背景

角色设计稿、表情稿、服装道具和场景设定图都可能经历重新生成。请求失败或页面刷新后，数据库里的请求状态不能代替当前页执行状态；否则 `generating` 会造成永久禁用，而 `error` 会遮住仍可使用的旧图。

本文影响漫画角色页、场景页、首话引导、下载记录和工作区来源准备入口。

## 当前规则

- 已确认图片与最新请求分别处理：当前状态为 `done` 时使用当前图，否则只允许直接 `previousImage.status=done` 作为可用旧图。未完成或错误的旧状态不能当成可用产物。
- 当前页的确认流程 `loading/submitting` 负责禁用生成按钮。只有数据库 `generating` 时，界面提示生成结果待确认，并提供重新生成入口；不自行宣称服务端任务仍在执行或必然失败。
- 重新生成仍经原有图片预览与费用确认弹窗，不能在恢复页面、读取状态或展示旧图时隐式调用模型。
- 旧图可见时仍展示最新错误或待确认提示。图片、版本徽章、角色/场景列表和首话引导必须对同一已确认产物保持一致。
- 图片 URL 使用已确认图的 `revision`。正在执行的新请求不能改变旧图的版本指向。
- 导出错误读取 `ComicExportJob.artifacts.error`。文件缺失、服务重启或图片处理失败都可能导致导出失败，界面不能一律解释为缺图。
- 下载记录中的重新导出绑定该记录的 `episodeId` 和格式，不受顶部当前选中话数影响。服务端继续验证图片完整性；失败原因保留在记录中。
- 原创与文本项目缺少故事资料时，工作区卡片也应提供整理入口；创建草稿与调用 AI 整理资料是两个明确动作。整理失败允许在同一项目重试。

## 维护边界

- `client/src/pages/comic/project/assets/` 只负责产物投影，不判定任务租约或故事语义。
- 图片执行互斥和版本发布属于服务端；前端不能据保存时间猜任务存活状态。
- `client/src/pages/comic/project/export/` 负责导出错误与下载记录，不通过源图片状态掩盖导出任务的错误。

## 验证

`referenceImageRecovery.test.mjs` 直接运行真实 React 组件的事件函数，验证恢复按钮、当前页禁用、旧图片版本、跨话导出重试及来源准备入口。`comicProduction.test.mjs` 覆盖既有首话引导、批量恢复与导出完整性。界面实际交互验收由用户完成。
