# 漫画图片版本与整话导出

## 背景

漫画格子的分镜、对白、图片和植字属于同一份成品的不同版本。生成可能持续较久，用户可能同时编辑对白、重抽图片或启动另一批任务。如果文件以固定名称覆盖，即使数据库阻止旧任务提交，迟到的文件写入仍会覆盖用户已确认的新图。目录里存在文件也不能证明该格已有可用成品。

规则影响范围：漫画角色与场景参考素材、单格生图、批量生图、对白编辑、植字、图片 HTTP 响应和整话导出。小说正文与其他图片业务不使用此版本合同。

## 决策与当前规则

### 以数据库确认的版本作为唯一图片来源

每次格子生图与植字使用独立 revision 目录，文件写好并校验可解码后才更新数据库。生图提交必须同时满足生成前的
`visualPrompt`、`dialogues`、`characterRefs`、`sceneRef` 和
`imageData`；这些结构化输入发生变化时，旧结果只能成为未发布候选文件，不能覆盖当前图片。

图片 metadata 的 `sourceFingerprint`
是上述输入的确定性身份摘要，不承担语义判断。语义规划和画面内容仍由 AI 决定。批处理还继承执行围栏，使失去任务租约的旧执行者无法提交数据库写入。

重抽过程保存
`previousImage`，保留前一张已确认图片。生成失败、取消、文件损坏或最终保存冲突不能删除旧图。只有新图片提交成功时才清空旧植字。修改对白/画面或重新生成分镜必须使旧图和植字失效，因为图像模型生成的原图可能含有旧对白。

### 植字必须匹配图片与对白

`letteredData.sourceFingerprint`
绑定已确认图片 metadata 与 panel 输入摘要。只有它与当前来源完全一致，并且对应 revision 文件存在，植字才可显示或导出。

不要读取目录里遗留的固定
`lettered.png`。旧植字缺少来源证据，无法证明对应当前图片/对白；兼容它会把已删除的台词重新带入导出。历史原图只有在
`imageData` 确认 `done` 时才允许按旧固定文件名读取，新生成器不覆盖或删除该文件。

当前图像生成提示包含对白绘制要求，植字是额外的本地排版能力，不应默认把同一对白再次叠加到已带字原图。若产品改用“无字生图后统一植字”，须同时调整 Prompt
Registry 的产品合同与默认生产步骤。

### 整话导出是完整的冻结快照

整话导出必须涵盖该话快照的全部格子。任一格无确认图片、来源失效、文件丢失或文件不可解码时，导出失败并报告格子序号，不能静默跳过后把残缺内容标记完成。

导出开始时将 panel 顺序、分镜输入、原图和植字 metadata 保存到任务
`spec.inputSnapshot`，并将实际读取的图片复制进任务私有 `inputs/`
目录。后续对白编辑、重抽和分镜重建不改变这次导出的源文件与元数据。

图片按目标宽度逐格归一化，再逐片裁取合成；不先创建整话大画布。单片必须满足编码尺寸和像素限制，长图过长时也自动返回多张产物。调用方必须展示完整
`artifacts` 列表，不能只下载第一张。

只有完成任务中已登记的产物可供下载；候选图片、冻结输入、处理中/失败任务的半成品不能通过目录猜测下载。

### 角色、表情、道具与场景参考素材

参考素材与格子图遵循同一条发布原则：模型生成和手动上传都写独立 revision，验证可解码后才更新 metadata。存盘顺序或目录内扩展名顺序不能决定当前图片，否则 PNG 后上传 JPG 时仍可能读到旧 PNG。

素材 CAS 绑定设计字段、项目画风和状态 JSON；资产同时绑定角色外观与三视图来源，表情绑定对应三视图。表情写入比较整个角色
`sheetData`，禁止读取新 JSON 后无条件合并旧表情结果。三视图成功换版时清除旧表情；失败保留前一张确认三视图。脸部与表情裁剪按来源 revision 隔离，不能用固定裁剪文件和 mtime 推断其来源。

当前图片及最近 5 个历史版本从 metadata 解析；显式 `revision`
的下载只能返回已登记的对应版本，不能忽略参数并返回新图。普通当前图片读取须校验设计摘要；历史读取保留其原始输入语义。旧固定文件仅在确认 metadata 或历史登记存在时兼容。删除素材记录不自动清理文件，因为已有格子和导出可能仍引用它；文件清理必须经过引用检查与备份。

单格生成的素材路径和预览 metadata 必须一一对应。每张确认原图独立传给模型并携带其 revision，不能把多个可独立排除的素材合成一张图片后仍按 metadata 索引筛路径。默认服装由角色三视图承载，只有分镜明确选择变体时才加入相应服装资产。预览展示全部候选，生成先执行用户排除，再校验最多 16 张；超量须报告并让用户缩减，禁止静默截断。若其他调用方合成参考图，画布尺寸以 sharp 编码输出
`info` 为准，不能把输入 `metadata` 当作缩放结果。

### 导出中断与恢复

导出 `processing` 状态必须持有有效租约。`updatedAt`
每 15 秒更新一次，90 秒无更新视为中断；列表或详情读取通过状态与过期条件 CAS 标记可重试错误。此判断不依赖当前进程持有任务集合，因此不会误伤另一进程的活跃导出。

心跳和成品提交必须校验租约仍有效，不能依赖用户轮询触发恢复。任务进入 `done` 或
`error`
后，迟到回调不得覆盖终态。恢复保留冻结快照和输入文件，并提示用户重新导出；不得把编辑后的当前格子拼接到旧任务快照中自动重跑。

## 失败模式与排查

- 显示的图和对白不符：比较 panel 输入摘要、`imageData.sourceFingerprint` 和
  `letteredData.sourceFingerprint`，检查编辑路径是否清理派生状态。
- 重抽后仍显示旧图：先看新 revision 是否被数据库确认；失败时继续保留旧图属于数据保护行为。
- 旧批任务生成完成但没有发布：检查 CAS 冲突与执行围栏的租约状态，不得绕过围栏重新强制保存。
- 长话导出失败或缺页：检查全部
  `artifacts`、每片高度、输入快照的格子数，以及缺失格序号；不要以扫描文件目录补全来源。
- 存储里有未引用文件：它们可能是取消/冲突后的候选，不代表业务完成。旧 revision 也可能仍由规划备份或导出引用。未经引用检查与备份，不做自动清理。

## 相关模块与验证

- `server/src/services/comic/assets/`：图片来源、revision 和原图发布。
- `server/src/services/comic/export/`：安全尺寸与逐片渲染。
- `ComicPanelImageService`、`ComicBubbleLayoutService`、`ComicExportService`：应用服务入口。
- `server/tests/comicAssetConsistency.test.js`：临时图片、并发生图、旧植字、切片像素与完整导出回归。
- `server/tests/comicPanelPublication.test.js`：独立临时 SQLite 的源数据 CAS 与原子植字失效。
- `server/tests/comicReferencePublication.test.js`：参考素材并发、上传编码、历史版本、裁剪来源与旧图保留。
- `server/tests/comicReferenceAssembly.test.js`：真实图片缩放、预览与输入配对、排除以及参考数量边界。
- `server/tests/comicExportRecovery.test.js`：导出租约、读时中断恢复与终态保护。
