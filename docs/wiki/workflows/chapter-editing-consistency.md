# 章节编辑、重写与审校的正文版本边界

## 背景

正文编辑器、自动保存、章节审校和后台生成都可能同时操作同一章节。仅比较当前界面的文字，不能阻止旧网络请求晚到后覆盖新稿；只按章节 ID 保存审校结果，也会把旧正文的问题用于修复新正文。

本规则影响专业工作台、章节编辑器、正文 PUT 接口和手动重写入口。自动导演的生成提交还应在自身落库边界维护正文版本条件。

章节定稿、流水线审校状态与验收事实同样属于正文版本的派生结果。长时间审校返回后，不能只按章节 ID 标记完成或写入旧正文的事实。

## 当前规则

### 正文更新的比较并交换

- HTTP 更新正文时必须同时提交 `content` 和 `expectedContent`。后者是客户端读取的完整原始正文，允许 `null`，不得用编辑器格式化后的文本替代。
- 数据库的同一次更新必须同时匹配章节 ID、小说 ID 和 `expectedContent`；版本冲突返回 HTTP 409，不能先更新再检查。
- 冲突请求不得同步摘要、事实、卷规划投影或 RAG。标题、执行策略等不包含 `content` 的 patch 不需要正文版本参数。
- 使用正文内容作为版本基线不需要增加数据库字段，也不会把任务状态或审校分数的修改误判成正文冲突。
- 核心服务与 HTTP 都必须拒绝缺少正文基线的覆盖，防止内部工具绕过接口校验。

### AI 工具的写入来源

- 正文读取工具同时返回展示用 `content` 和原样保留空白、`null` 的 `expectedContent`。草稿保存与整章补丁要求该显式版本；不能在生成完成后临时重读新稿并把新稿当成旧结果的基线。
- 用户提供草稿的保存工作流先读取目标章，再保存。执行上下文只把同一小说、同一章的读取结果绑定给后续写入；按序号保存时同时解析对应章节 ID，已有显式基线不得被覆盖。
- 追加与局部替换是读取正文后的确定性操作，可以使用执行时读取的正文，但提交仍须原子比较该正文，拒绝读取与写入之间发生的并发变化。
- 用户拒绝补丁审批后，只能生成未应用的差异预览。`save_chapter_draft` 仍会覆盖章节正文，不能当成规避审批的替代保存入口。

### 编辑会话

- 同一小说、同一章节的自动保存、手动保存和 AI 候选应用共用一条写入队列。一个请求未完成时，后续等待稿合并为最新内容；下一次请求使用前一次成功确认的正文作为基线。
- 保存成功只确认本次提交的稿件。用户在请求期间继续输入时，较新的草稿和本地缓存必须保留。
- 本地缓存保存正文及其原稿基线。历史纯文本缓存或基线不同的缓存只能作为待核对草稿，不得自动覆盖服务器新稿。
- 编辑器组件身份仅由小说 ID 和章节 ID 决定，不能把 `updatedAt` 放进 React key 强制销毁编辑会话。
- 冲突时展示服务器稿并保留本地稿。用户明确选择保留本地修改前，应先创建服务器稿快照；后续写入仍必须使用版本条件。
- AI 候选版本绑定预览请求的正文。应用前先确认该原稿保存成功，再等待备份取得快照 ID；备份期间正文变化时必须重新核对，不能用旧文本位置改写新稿。

### 重写与审校

- “重写本章”不能先清空正文。必须等待原稿快照持久成功并取得快照 ID，再开始生成；生成失败时原稿继续可用。
- 审校结果绑定请求开始时的小说 ID、章节 ID 和正文内容。请求完成回调不得用完成时的当前选中章节替代请求源。
- 切换章节、切换作品或正文发生变化后，旧审校结果不能显示为当前章结果，也不能传入自动修复。新审校或重新加载后，以匹配当前正文的结果为准。

### 后台定稿状态与事实

- `ChapterContentFinalizationService` 在 `chapter_content` 执行围栏内处理验收、状态和事实。围栏携带小说 ID、章节 ID 及实际处理正文，并由 Prisma 持久化边界在每次写入事务内锁定、核对章节；不能用写入前的独立查询代替原子校验。
- 流水线向 `reviewed`、`approved`、`needs_repair` 的状态推进必须传递本轮正文。同一次数据库更新匹配该正文，不能把旧稿审校结果应用到编辑器刚保存的新稿。
- 验收事实仍以批量追加方式写入；正文围栏冲突必须上抛 `ExecutionStoppedError`，不能清空已有事实，也不能作为普通事实同步告警吞掉。
- 正文冲突属于并发数据一致性失败，与章节局部质量债不同。停止旧稿的派生写入可以保护新稿，不应把冲突转译为要求小说结构重规划。

## 失败诊断

- **显示已保存但刷新变回旧稿**：检查是否有绕开章节保存队列的正文 PUT，以及数据库更新是否携带正文比较条件。
- **保存时继续输入后文字消失**：检查成功回调是否无条件清空缓存、覆盖当前草稿，或父组件是否因 `updatedAt` 重挂载。
- **修复插入了别章人物或事件**：检查审校结果的 `source` 是否与当前小说、章节和正文完全匹配。
