# 漫画批量生产与恢复

## 背景与范围

一话漫画的图片生成有外部费用，可能跨越页面关闭、接口断开或服务重启。内存队列和计数不能证明哪些格已经完成，也不能用于恢复费用授权。此规则适用于漫画单话批量图片、任务投影、规划互斥和共享图片运行时的模型一致性检查；不改变小说自动导演的质量门禁。

## 任务与确认合同

`ComicBatchJob` 的 `type=episode_image_batch`，必须写入 `episodeId`。`progress`
版本 1 保存
`episodeId`、`provider`、`imageModel`、`concurrency`、目标格、完成格、失败格、错误、每格源指纹与初始图片版本，以及执行租约。计数由已完成/失败格集合推导。规划归档不属于生产任务，不进入批量列表。

估算返回待生成数量、实际解析的模型和
`scopeFingerprint`，不能用历史模型固定单价充当可靠报价。前端确认绑定该范围；创建时复核格子内容、图片和模型，变化后要求重新确认。模型解析在发送请求前必须符合任务的
`expectedModel`，避免运行期间修改设置后静默切换费用与效果。

结构化指纹用于并发和输入验证，不作语义路由。剧情分话与格子内容继续由注册 AI
Prompt 决定。

## 执行权与持久化

创建/继续在短事务中锁住话记录，检查是否有同话有效任务。规划替换采用相同话锁，因此不能跨越已经开始的生图任务覆盖脚本。默认租约 90 秒，每 20 秒心跳；有效期限只由控制面续约，图片写入围栏检查不会延长租约。

每个执行者携带唯一 `leaseOwner`。进度和心跳写入串行化，以旧 `progress`
全文进行条件更新，避免多个格同时完成时覆盖计数。图片业务写入通过
`platform/execution` 的 `comic_batch`
围栏，在同一数据库事务内检查任务类型、运行状态、租约所有者和期限；提交前再查一次。

批量执行不继承创建 HTTP 请求的取消信号。用户停止通过持久任务状态撤回执行权，当前进程也中止后续派发。外部平台已接受的请求可能仍计费，但迟到图片只能留下未发布候选文件，不能覆盖新任务结果。

## 终态与恢复

| 状态          | 含义与下一步                           |
| ------------- | -------------------------------------- |
| `running`     | 有效租约正在处理持久目标，页面轮询进度 |
| `completed`   | 目标全部完成，可进入审阅/导出          |
| `partial`     | 部分格失败，确认后只重试剩余格         |
| `interrupted` | 租约过期或进度存储失败，确认后继续     |
| `cancelled`   | 用户停止后续生成，可显式继续           |

GET 查询只投影过期状态，不自动续费或生成。缺少话 ID、目标集合或模型证据的旧任务标为不可直接恢复，用户需从对应话重新确认，禁止用项目最新任务猜测关联。

恢复先复核每格源指纹和原模型。已发布新图片但尚未来得及保存进度的格，通过初始图片版本对比认定完成，从而避免服务崩溃后再次付费。显式重抽失败时保留的旧图不能被算作本次新图成功。分镜有修改或格子被替换则拒绝旧任务恢复，允许重新确认开启新任务。

进度写入失败必须停止继续派发，尝试保存中断状态；数据库完全不可用时由原租约到期保证恢复入口，不能吞掉错误并永久显示运行中。

## 排查与验证

- 重复提交：检查话行锁和活动租约，再查前端同步提交锁。
- 旧任务覆盖新图：检查 immutable 图片 revision、任务 owner、图片源 CAS 和围栏是否在同一事务。
- 恢复重复出图：检查目标、初始图片版本和已完成格，而非只看计数。
- 修改分镜后无法新开：确认前端只禁止运行中任务，旧任务不可恢复不应禁用重新确认入口。
- 覆盖测试：`comicBatchProduction.test.js`
  使用独立临时 SQLite 验证并发领取、恢复、停止、存储失败和模型变化；共享执行围栏回归保护小说原有合同。
