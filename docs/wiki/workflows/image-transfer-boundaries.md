# 图片模型调用与文件传输边界

## 背景与范围

漫画参考图的一致性不仅取决于分镜与 Prompt。界面确认了多张素材而底层只上传第一张，会让角色、道具和场景约束丢失。模型已经返回下载地址，也不代表图片下载可以无限等待或无限写盘。

本规则适用于 `services/image/provider.ts` 和
`services/image/infrastructure/`，覆盖漫画、小说封面、角色图片及其他复用图片运行器的入口。漫画上传 API 的限制只作用于漫画素材、场景上传。

## 当前合同

- 本地路径与 URL 参考图都属于用户选定的输入，合计最多 16 张，不以路径优先级丢弃 URL，也不截断列表。参考图走 edits
  multipart，单图使用 `image`，多图使用 `image[]`，每个文件声明实际编码类型。
- URL 参考图先通过受限下载器写入本次临时目录，和本地文件一并上传。单张参考图最多 20
  MiB，上传文件合计最多 64
  MiB；只接受 PNG、JPEG、WebP。仅本次请求创建的临时参考目录可在结束时清理。
- 无参考图使用 generations 请求。未接入参考图的通道必须明确失败；不能丢掉参考图继续发起付费调用。不同兼容供应商是否实现多图 edits，仍需部署者使用自己的通道验收。
- Provider 请求同时受执行取消信号和配置的 HTTP 超时控制。取消不表示上游已经撤销计费，已发送请求的费用由供应商决定。下载器独立设置 90 秒期限，并继承执行和调用方信号。
- 生成结果下载默认最多 32 MiB。声明长度、无长度响应流和 data
  URI 使用同一上限。下载按块写独立 `.partial-UUID`
  文件，完成后才替换目标；失败不损坏已有目标文件，错误不回显签名下载地址。
- 漫画上传 API 自身限制 20
  MiB，不能只依赖 Nginx。错误媒体类型、空数据与超限请求须在业务持久化前拒绝；后续发布阶段继续校验真实图片编码和可解码性。

## 维护原则与排查

图片传输层负责字节、超时与取消，漫画资产模块负责 revision、来源摘要和数据库发布。传输成功不能绕过资产的并发校验。运行器仍通过模块门面引用下载服务，不让漫画业务直接管理临时下载文件。

模型忽略角色或场景时，先比较预览数量、过滤后的文件数量与 multipart 数量，再检查通道对多图 edits 的支持；不要靠修改 Prompt 掩盖图片漏传。停止后仍有 HTTP 请求时，检查执行作用域是否传播到 provider 与下载器。

## 对应验证

- `imageProviderReferences.test.js`：本地与 URL 素材的实际上传字节、参数传递、参考图拒绝边界和执行取消。
- `imageDownloadSafety.test.js`：执行取消、有/无长度超限、data
  URI 限制、字节保存与错误脱敏。
- `comicHttpBoundary.test.js`：真实 HTTP 空请求、输入校验、上传限制、revision 与排除素材传递。
