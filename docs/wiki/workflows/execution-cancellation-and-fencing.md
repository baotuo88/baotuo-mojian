# 执行取消与持久化围栏

## 背景

LLM、异步工具和数据库操作可能在调用方停止等待后继续执行。仅把任务标记为取消，或用 `Promise.race` 提前返回，不能阻止旧执行保存结果。自动导演还存在租约转移：同一个命令可以由另一个 Worker 接管，因此必须区分命令身份与本次执行身份。

本规则影响自动导演 Worker、Agent 执行与审批续跑、Creative Hub、LLM 调用，以及这些执行路径中的数据库写入。不改变章节质量债与全局重新规划的区分；取消和失去执行权属于运行安全边界，不是章节质量判断。

## 决策

执行作用域归 `server/src/platform/execution/` 所有，通过门面提供信号与持久化围栏。业务入口负责绑定执行身份；数据库适配器负责阻止没有执行权的结果写入。

- 自动导演身份由 `commandId + leaseOwner + attempt` 确定，还必须满足租约未过期、命令仍在执行、所属任务未取消。
- 明确的 `cancel` 控制命令可收束已取消任务，但必须核对数据库中的命令类型、owner、attempt 和有效租约；不能把任务取消条件的例外用于生产命令，也不能绕过调度前和逐次保存时的执行权检查。
- Agent 运行必须未处于 `cancelled`。进程内取消同时中止该 run 的全部活动控制器；其他实例依靠数据库中的取消状态拒绝迟到写入。
- 章节衍生结果使用 `chapter_content` 围栏绑定 `novelId + chapterId + content`。审校、事实入账与状态收束仅在正文仍等于启动时的版本时落库；正文不匹配是数据完整性中断，不得降级成章节质量债后继续保存。
- 快照资料重建使用 `snapshot_restore` 围栏绑定 checkpoint ID 和领取时的完整 metadata；仅 `running` 且 metadata 匹配的领取者可继续写入。围栏锁不推进心跳时间，心跳和领取者终态更新由恢复服务单独负责。
- LLM 与异步工具应使用 `getExecutionAbortSignal()` 并在执行边界调用 `throwIfExecutionAborted()`。不遵守信号的适配器仍须通过数据库围栏。

## 持久化规则

共享 `db/prisma` 客户端在执行作用域内将写入与执行权检查放入短事务：先锁定对应执行行，再保存结果，提交前重新检查信号、执行状态和租约期限。事务期间取消获胜时，已经写入但尚未提交的结果必须回滚。

单条模型写入、原始写 SQL、交互式事务和 Prisma 数组事务均受保护。数组事务保留 Prisma 操作的惰性语义，在同一个短事务中按原顺序执行。不得混用其他 Prisma 客户端创建的数组操作。

章节正文围栏通过参数化原地 SQL 更新获取行锁，并在提交前再次核验正文；该锁不推进 `updatedAt`，避免把审校保存误判为一次正文编辑。`null` 与空正文保持区别，不做归一化匹配。围栏包裹衍生数据写入，不包裹预期改变正文的首次保存。

不要把模型调用、整轮规划或整本生产放进数据库事务。只有持久化阶段持有执行行锁。新模块应使用共享 Prisma 门面；不要创建未接入围栏的业务客户端。

全部执行身份应在打开短事务前绑定。在已经持有围栏的事务内部追加不同身份会被拒绝并回滚，防止新身份错误继承“已校验”标记，或通过嵌套独立事务破坏原子性。

已经结束的执行作用域不能给迟到回调提供写权限。独立后台任务应有自己的持久任务身份及 Worker 入口；它的生命周期不能隐式继承已经结束的导演命令。

## 取消和终态

- Worker 从领取命令开始续租，确认首次续租成功后进入执行。续租失败或本地租约期限到达时立刻中止信号。等待资源配额也必须响应该信号。
- Agent 的取消是控制面操作，不能等待覆盖整轮执行的运行锁。先发出进程内中止信号并写入取消状态，再处理未决审批。
- 工具调用前后、开始下一个工具前、写成功终态前都要检查取消。成功或失败更新不能覆盖已经持久化的 `cancelled` 状态。
- Creative Hub 只收束当前 invocation 创建的 run。图取消后结束仍活动的 run；图异常后记录失败，避免残留 `running` 阻塞下一轮。
- 已持久化的 `waiting_approval` 是待用户处理的工作，关闭流连接不应自动拒绝它。显式取消任务仍按取消合同处理。

## 清理边界

`withoutExecutionScope()` 仅供控制面清理，例如取消登记、当前 invocation 的终态收束、释放资源预约。失去执行权的旧 Worker 不得借此保存章节、规划、角色状态或其他生产结果，也不得覆盖接管者维护的任务状态。

## 诊断与验证

1. 确认活动 scope 的命令 ID、owner、attempt 与数据库当前行一致。
2. 检查续租失败后信号是否中止，及调用链是否继续发起 LLM 请求。
3. 若第三方调用不响应取消，让它延迟返回，验证实际数据库写入被拒绝。
4. 在事务中写入后触发取消，确认整笔事务回滚。
5. 在 Creative Hub 图节点间触发中止，确认当前 run 收束且下一轮可创建新 run。

回归入口包括 `executionPersistenceFence.test.js`、`directorWorker.test.js`、`agentExecutionCancellation.test.js` 和 `creativeHubExecutionLifecycle.test.js`。数据库回归只使用独立临时 SQLite，不读取业务小说。
