# 漫画源章节映射、规划替换与事实版本

## 背景

漫画的一话可能对应小说的多个章节，漫画话序不代表小说章序。如果结构化规划只保存大纲而丢弃章节区间，下游很容易读到错误正文，生成表面连贯但脱离原著的分镜。另一方面，漫画原稿包含昂贵的角色图、分格图与人工编辑，重新规划必须保留这些可恢复资料。

本文影响小说导入、漫画分话、分镜、跨话事实，以及它们与图片生产任务的并发边界。

## 当前规则

### 章节映射是 AI 产物

- `comic.episodeOutline` 返回每话 `sourceChapterStart/sourceChapterEnd`，应用服务校验后写入 `ComicEpisode.scriptConfig.sourceRange={start,end}`。
- 区间必须是已导入节拍中存在的连续小说章节。确定性代码只验证编号、边界、连续性，不决定改编情节对应关系。
- 旧项目缺少映射时，`comic.sourceMapping` 根据现有大纲与源章节节拍补充映射。无法匹配必须明确失败，不能用“第 N 话对应第 N 章”代替语义判断。
- 分镜生成读取映射范围的完整正文。第一次补旧映射时不信任旧的无来源正文快照；后续正常生成复用已保存快照，只有显式刷新正文才回读源小说。
- 分镜配置更新必须保留 `sourceRange`。Prompt 不得只截取正文开头或节拍前若干项，避免关键结局被静默丢弃。
- 每次规划返回的话序、数量，及分镜返回的格序必须与请求范围一致；无效结构不得写入现有作品。

### 导入保留漫画资产身份

小说角色使用 `sourceCharacterRef` 对应已有漫画角色；没有来源 ID 的内容源只匹配同名且同样没有来源 ID 的记录。已存在角色保留 ID、外貌编辑、性别、设计稿、资产关系。新增来源角色可补入，来源中暂时消失的角色不会自动删除，避免破坏已有话数。

漫画角色是导入后可独立编辑的资产。源小说角色更新不应覆盖用户已确认的漫画视觉设计。

### 替换必须有可验证原稿

- `replaceExisting=true` 表示用户选择了重新规划/重新分镜；没有此输入时，服务在调用模型前返回冲突，避免花费后才告知无法替换。
- 提交事务先保存 `ComicBatchJob(type=planning_backup,status=completed)`，其中 `progress` 记录完整原分话、原分镜和本话事实，包含图片元数据与文件引用；随后回读并验证完整内容。
- 备份失败、校验失败或并发内容变化，整个替换事务失败，原记录不变。
- 规划替换不会删除图片文件。归档是恢复原稿的依据，不能混入图片生产任务列表或被当成待重试生产任务。

### 并发与跨话事实

模型调用不占数据库事务。写入前对分话做条件 no-op 更新以获得行锁，再检查有效生产租约和分镜内容指纹。多话替换按分话 ID 排序获取锁。no-op 保留 `updatedAt`，否则锁操作本身会改变预期指纹，误判为外部修改。

漫画图片批量任务是否仍活跃由 `production` 模块租约规则决定。过期的 `running` 记录不能永久阻止重新规划。

事实只引用本话之前的可信事实，不把本话旧脚本或未来话的事实作为既成事件。AI 提取结束后，在同一分话锁内复核脚本版本和格子内容；旧脚本的迟到提取不允许写入。已有本话事实更换前需要归档。对白或画面脚本编辑也先取得分话锁，图片状态与植字状态随编辑失效，防止旧图被误认作新稿。

## 验证与诊断

- 第一话覆盖第 1–3 章时，检查配置区间、传给适配器的范围和 Prompt 尾部正文是否一致。
- 重新规划误报并发冲突，检查锁操作是否修改了时间戳；分话锁必须是条件 no-op。
- 已停止的任务阻止规划，检查租约是否过期，不要仅按 `status=running` 判断。
- 跨话事实与分镜不一致，先比较脚本版本与格子内容指纹，不能靠再次追加事实修补。
- `server/tests/comicPlanningReliability.test.js` 包括真实临时 SQLite 的成功替换、备份失败回滚，以及 mock 模型的映射和迟到结果回归；不使用业务数据库或真实模型。
